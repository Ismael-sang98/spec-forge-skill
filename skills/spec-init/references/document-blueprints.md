# SpecForge — Document Blueprints & State Schema

Every document generated by `spec-init` must be concrete, exhaustive, and free of `[TODO]` or `[TBD]` placeholders. Keep numbered filename prefixes (`01_PRD.md`, `02_TRD...`, etc.) intact so automated gates and cross-references remain deterministic regardless of document language.

---

## 0. `docs/.spec-state.json` (Resumable Gate Tracker)

```json
{
  "specForgeVersion": "1.0.0",
  "projectName": "ExampleApp",
  "platform": "web | mobile | desktop | backend | cli",
  "profile": "full | lean",
  "conversationLanguage": "fr",
  "docsLanguage": "fr",
  "status": "IN_PROGRESS",
  "currentPhase": 1,
  "completedPhases": [],
  "stackSummary": "",
  "verifyCommand": "",
  "updatedAt": "2026-10-29T15:30:00Z",
  "unlockedAt": null
}
```

Valid `status` values:
- `"IN_PROGRESS"` — Blocks all code writes outside `docs/` and root governance files.
- `"READY_TO_CODE"` — Unlocks code writes strictly governed by `AGENTS.md` and `docs/07_IMPLEMENTATION_PLAN.md`.

## 1. `docs/GLOSSARY.md` (Ubiquitous Language — DDD)

Must contain:
- Purpose statement: every variable, class, API payload field, and DB table/column MUST use the exact **Canonical Code Identifier (English)** defined here.
- Markdown table:
  | Domain Term (Doc Language) | Canonical Code / DB Identifier (English) | Forbidden Synonyms | Strict Business Definition |
  | :--- | :--- | :--- | :--- |
- Core domain enumerations (exact enum identifiers + business meaning).

## 2. `docs/01_PRD.md` (Product Requirements Document)

Must contain:
1. **Executive Vision & Problem Statement** (what problem, target audience, platform, non-goals / out-of-scope).
2. **Personas & User Roles Summary**.
3. **Global Business Invariants** (non-negotiable laws: e.g., currency integer representation, server-side-only calculations, immutability of issued invoices/audit logs, timezone/UTC policy).
4. **Functional Modules Breakdown** (Module 1..N: user stories, inputs, exact step-by-step business rules, edge cases).
5. **Exact Mathematical & Domain Formulas** (worked numerical examples included so unit tests can assert exact expected outputs!).

---

## 3. `docs/02_TRD_TECHNICAL_SPEC.md` (Technical Requirements Document)

Must contain:
1. **System Architecture & Stack Matrix** (Frontend/Client, Backend/API, Database, ORM, Auth, Hosting, Third-Party Services, Mermaid architecture diagram).
2. **Authentication, Session & Security Architecture** (JWT/Cookies/OAuth/API Keys, password hashing, CORS, CSRF, rate-limiting tiers).
3. **Complete API / IPC / Command Contracts**:
   - Every endpoint or command grouped by domain: Method + Path, Auth/Role required, Request Validation Schema (fields + constraints), Success Response payload, Error codes from `ERROR_CATALOG.md`.
4. **Transactional & Concurrency Algorithms** (explicit ACID `transaction` boundaries whenever an operation mutates >= 2 tables or external states).
5. **Background Jobs, Offline Sync, Storage & External Webhooks** (retry policy, idempotency keys, signed URL TTLs).
6. **Environment Variables Specification** (synced 1:1 with `.env.example`).

---

## 4. `docs/03_APPFLOW.md` (User Flows, Routing & State Machines)

Must contain:
1. **Complete Route / Screen / Command Map** (Path/Screen ID, Access Level, Purpose, Entry/Exit transitions).
2. **Finite State Machines (Mermaid `stateDiagram-v2`)** for every stateful domain entity:
   - Allowed transitions, trigger actor/event, side effects (notifications, audit logs), and explicitly **forbidden transitions**.
3. **Critical End-to-End Sequence Diagrams (Mermaid `sequenceDiagram`)** (e.g., Auth lifecycle, core business checkout/workflow, error recovery / offline sync).

---

## 5. `docs/04_DATABASE_SCHEMA.md` (Data Model & Persistence)

Must contain:
1. **Entity-Relationship Diagram (Mermaid `erDiagram`)**.
2. **Formal Schema Definition** (complete Prisma schema, SQL DDL, Drizzle/TypeORM, SwiftData/Drift/SQLite, or MongoDB/Firestore collection schemas + security rules).
3. **Data Dictionary Table-by-Table** (columns, exact types, nullability, defaults, `ON DELETE` cascade/restrict rules).
4. **Indexes & Performance Constraints** (composite unique constraints, foreign-key indexes, query hot-paths).
5. **Seed & Reference Data Specification** (required bootstrap data, with production guard forbidding destructive seeding when `ENV=production`).

---

## 6. `docs/05_UI_UX_DESIGN.md` *(GUI Projects)* OR `docs/05_INTERFACE_CONTRACT.md` *(Headless API/CLI)*

### For GUI Projects (`05_UI_UX_DESIGN.md`):
1. **Design Tokens**:
   - Exact Hex Color Palette (Brand Primary, Brand Accent, Backgrounds, Surfaces, Text hierarchy, Semantic Success/Warning/Danger).
   - Typography Scale (font families, sizes, weights, line heights).
   - Geometry, Spacing & Elevation (border radii, shadows, grid/breakpoints, touch targets).
2. **Reusable Core Components Spec** (Buttons, Inputs, Modals/Drawers, Tables/Lists, Status Badges, Empty/Loading/Error states).
3. **Screen-by-Screen Mapping & Layout Spec** (referencing `docs/maquettes/` files when available, or structured wireframe layout + interactive states for every route in `03_APPFLOW.md`).
4. **Accessibility & Responsive / Platform Adaptation Rules** (keyboard nav, contrast, mobile safe areas).

### For Headless API / CLI Projects (`05_INTERFACE_CONTRACT.md`):
1. **Wire Protocol / CLI Ergonomics** (OpenAPI 3.1 / GraphQL / gRPC contract conventions, or CLI command hierarchy, flags, POSIX exit codes, JSON vs human output modes, progress/error formatting).
2. **Pagination, Filtering, Versioning & Idempotency Standards**.

## 7. `docs/06_CODING_RULES.md` (Engineering Standards & Clean Architecture)

Must contain (tailored via [stack-profiles.md](./stack-profiles.md)):
1. **The Golden Coding Commandments** (strict typing, zero `any`/`dynamic`, schema validation at all boundaries, modularity cap <= 200 lines per component/file).
2. **Canonical Folder & Module Structure** (exact directory tree of the target codebase).
3. **Layer Responsibilities & Dependency Direction** (UI/Presentation -> State/Hooks -> Domain/Services -> Data/Repositories; business logic strictly banned from UI views).
4. **Error Handling, Logging & Security Hygiene** (never log tokens/passwords/PII, structured errors from `ERROR_CATALOG.md`).
5. **Git & Verification Discipline** (Conventional Commits, mandatory `verify` command pass before checking off any task).

---

## 8. `docs/07_IMPLEMENTATION_PLAN.md` (Vertical-Slice Roadmap)

Must contain:
- Execution rule banner: **Strict sequential vertical slices — Slice `N+1` cannot start until Slice `N` passes 100% of unit tests, `verify`, and acceptance criteria.**
- Ordered Slices (`Slice 0: Project Foundation & Tooling`, `Slice 1: Auth & Base Layout`, `Slice 2..K: Core Business Features`, `Final Slice: Production Hardening & PROD_CONFIG Audit`):
  - Each slice lists granular `[ ]` checkboxes across all layers:
    - `[ ]` Validation Schema / DTOs
    - `[ ]` Database Model & Migration
    - `[ ]` Domain Service & ACID Transactions
    - `[ ]` Unit & Integration Tests
    - `[ ]` API Endpoint / Controller / State Wiring
    - `[ ]` UI Screen / Component Integration
    - `[ ]` `verify` Command Green & Acceptance Criteria Validated

## 12. `docs/PROD_CONFIG.md` (Pre-Production Hardening & Audit Matrix)

Must contain a tabular audit checklist (`ID | Control Point | Dev/Demo Risk | Mandatory Production Action | Status`) across 6 pillars adapted to the platform:
1. **Application Security & Zero Secret/Token Leaks** (no reset tokens in responses/logs, rate limiting, strict cookies/CORS, startup fail-fast on missing secrets, removal/isolation of all demo/mock stores).
2. **Database Integrity, Migrations & Backups** (formal migrations only, seed script blocked in production, connection pooling, automated backups / RLS).
3. **Storage & File Privacy** (private buckets, short-lived signed URLs, upload MIME/size validation).
4. **External Integrations & Observability** (transactional emails/SPF/DKIM, webhook signature verification, structured error monitoring).
5. **Performance & Bundle/Binary Hardening** (pagination caps, indexes, asset compression, code signing for Mobile/Desktop).
6. **Deployment & Rollback Checklist**.

## 14. Root Governance Pack (`AGENTS.md`, `.cursorrules`, `CLAUDE.md`, `.env.example`)

- **`AGENTS.md`**:
  - Lists every document in `docs/` as the mandatory Single Source of Truth.
  - Lists the **12 Inviolable Commandments** customized to the project's domain and stack (e.g., strict types, boundary validation, exact currency/domain invariants, ACID transactions, UI token fidelity, file length cap <= 200 lines, state/fetching discipline, mandatory unit tests, sequential vertical slices, production lock via `PROD_CONFIG.md`, mandatory `verify` command, and mandatory structured closing report: Done / Remaining / Global Progress).
- **`.cursorrules` & `CLAUDE.md`**:
  - Mirror the exact project constitution and point to `AGENTS.md` + `docs/` so every developer in the team gets identical AI behavior regardless of IDE.
